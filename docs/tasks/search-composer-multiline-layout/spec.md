# search-composer-multiline-layout Spec

## Problem Statement
- 홈 검색, 검색 결과 검색, 가이드 목록 검색, 문서 내 질문 입력이 모두 단일 줄 input처럼 보여 긴 질문 입력과 chat형 검색 경험이 어색하다.
- 홈 검색 박스 폭과 추천 가이드 프레임 폭/라디우스가 달라 첫 화면 밀도가 어긋나고, 검색과 추천 가이드 사이 간격이 커서 한눈에 보기 어렵다.

## Business Context
- 이 위키는 검색 기반 탐색이 핵심이므로, 첫 화면과 검색 입력 UX가 실제 chat형 에이전트처럼 길고 자연스러운 질문 작성에 맞아야 한다.

## Scope
- 메인 검색, 검색 결과 페이지 검색, 가이드 목록 검색, 문서 내 질문 입력을 멀티라인 textarea 기반 composer로 변경한다.
- `Enter` 전송, `Shift+Enter` 줄바꿈 규칙을 공통 입력 경험으로 맞춘다.
- 홈 검색 컴포넌트 폭과 라디우스를 추천 가이드 프레임과 정렬한다.
- 홈 검색과 추천 가이드 사이 간격, 검색 영역 상하 여백을 줄여 첫 화면 밀도를 높인다.

## Out Of Scope
- 검색 랭킹, AI 답변 품질, 검색 API 동작은 변경하지 않는다.
- 추천 가이드 카드 구성 규칙(`guide` only, 시작 가이드 고정)은 변경하지 않는다.

## User Or Operator Scenarios
- 사용자가 홈에서 두세 줄짜리 자연어 질문을 입력하고 `Enter`로 바로 검색한다.
- 사용자가 문서 안 질문 패널에서 설명 문장과 예시를 줄바꿈해 작성하고 `Shift+Enter`로 개행한다.
- 사용자가 `/guides` 목록에서 여러 키워드를 줄바꿈 포함으로 입력해 좁은 한 줄 입력보다 읽기 쉬운 상태로 필터링한다.

## Acceptance Criteria
- AC1. 메인 검색, 검색 결과 검색, 가이드 목록 검색, 문서 내 질문 입력이 textarea 기반으로 보이고 높이가 기존보다 커진다.
- AC2. 위 입력기에서 `Enter`는 제출/검색, `Shift+Enter`는 줄바꿈으로 동작한다.
- AC3. 홈 검색 박스 폭과 외곽 라디우스가 추천 가이드 프레임과 시각적으로 일치한다.
- AC4. 홈 첫 화면에서 검색 박스와 추천 가이드 사이 간격 및 검색 상하 여백이 줄어 더 적은 스크롤로 함께 보인다.

## Edge Cases
- 빈 입력에서 `Enter`를 눌렀을 때 기존 빈 입력 가드 동작은 유지한다.
- IME 한글 조합 중 `Enter`는 조합 확정으로 처리되고 의도치 않은 제출이 발생하지 않아야 한다.

## Assumptions
- 기존 검색 버튼과 제출 동작은 유지하되 입력기만 multiline composer 패턴으로 맞춘다.
- 현재 시각 언어는 유지하고, 완전히 새로운 색/브랜드 방향은 도입하지 않는다.

## Clarifications
- Question: 벤치마크 기준은 무엇인가.
- Answer: ChatGPT, Claude, Perplexity 계열의 공통 composer 패턴인 멀티라인 입력, `Enter` 전송, `Shift+Enter` 줄바꿈, 넓은 하단 액션 버튼 정렬을 참고한다.
