# article-ask-panel-resize-and-scroll-fix Spec

## Problem Statement
문서 상세 페이지의 Ask 패널(`ArticleAskPanel.tsx`)에서 두 가지 버그가 보고됨:
1. 답변을 받아 패널 높이가 자동 확장(320px)된 상태에서 사용자가 마우스로 패널 상단 리사이즈 핸들을 드래그해 패널을 작게 줄이면, 전송 버튼이 패널의 둥근 하단 경계 밖으로 처져 보임.
2. 질문을 제출하고 답변이 완료되면, 턴 목록이 항상 컨테이너 최하단으로 스크롤되어 답변이 길 경우 답변의 끝부분만 보이고, 사용자가 답변을 읽으려면 매번 위로 다시 스크롤해야 함.

## Scope
- `ArticleAskPanel.tsx`의 턴 변경 시 자동 스크롤 로직 수정 — 컨테이너 최하단이 아니라 최신 턴의 상단으로 스크롤.
- `styles.css`의 `.article-ask-form`/`.article-ask` 레이아웃 수정 — 리사이즈 시 폼(및 버튼)이 항상 자연 크기를 유지하고, 극단적으로 작은 크기에서도 시각적으로 넘치지 않도록 클리핑.

## Out of Scope
- 리사이즈 가능한 최소 높이 값(64px) 자체의 변경.
- Ask 패널의 다른 기능(질문 입력, 텍스트 선택 연동 등) 변경.

## Root Cause
1. **스크롤 버그**: `useEffect(() => { turnsRef.current.scrollTop = turnsRef.current.scrollHeight }, [turns])`가 턴 배열이 바뀔 때마다(질문 추가 시, 답변 완료 시) 무조건 컨테이너의 절대 최하단으로 스크롤. 답변이 길면 답변의 시작 부분이 아니라 끝부분만 보임.
2. **리사이즈 버그**: `.article-ask-form`에 `shrink-0`이 없어, 패널을 작게 리사이즈하면 flex 알고리즘이 `.article-ask-turns`(이미 `flex-1 min-h-0`로 수축 가능하도록 설계됨)뿐 아니라 폼 영역도 함께 수축시킴. 게다가 폼의 실제 최소 필요 높이(버튼 + 패딩)가 리사이즈 드래그의 하드코딩된 최소값(64px)보다 미세하게 커서, `.article-ask`에 `overflow` 클리핑이 없으면 그 차이만큼 버튼이 패널 밖으로 삐져나옴.

## Acceptance Criteria
- AC1: 질문 제출 후 답변이 완료되면, 스크롤 위치가 최신 턴의 상단(질문 시작 지점)에 맞춰져 답변을 처음부터 읽을 수 있어야 한다.
- AC2: 패널을 최소 크기(64px)까지 리사이즈해도 전송 버튼이 패널의 둥근 경계 밖으로 시각적으로 넘치지 않아야 한다.
- AC3: 기존 동작(질문 입력, 텍스트 선택 연동, 답변 렌더링)에 회귀가 없어야 한다.

## Assumptions
- 리사이즈 최소값(64px)과 `.article-ask-turns`가 0까지 수축 가능한 것은 기존 설계를 그대로 유지 — 최소값 자체를 늘리는 대신 오버플로우 클리핑으로 시각적 문제를 해결.
