# guide-page-toc-sidebar-refresh Spec

## Problem Statement
- 가이드/문서 상세 페이지(`ArticlePage`, `StartingGuidePage`)의 목차(TOC)가 컨텐츠와 같은 그리드 트랙 안에 있어 시각적으로 완전히 분리된 사이드 패널처럼 보이지 않는다.
- 본문(`.article-body`)이 그리드 셀 내부에서 좌측 정렬되어 있어, TOC가 있는 화면에서 컨텐츠가 화면 중앙이 아니라 살짝 좌측으로 치우쳐 보인다.
- 하단 플로팅 검색(Ask) 패널(`.article-ask-dock`)은 뷰포트 기준 `fixed` + 자체 `max-width`로 위치가 계산되어, 컨텐츠 컬럼의 실제 중심과 폭이 정확히 맞물리지 않을 수 있다.
- Ask 패널이 바깥 컨테이너(`.article-ask`)와 내부 입력 폼(`.article-ask-form`)에 각각 보더를 갖고 있어 이중 테두리로 보인다. 높이와 라운드 처리도 다듬어지지 않아 딱딱한 인상을 준다.

## Business Context
- 최근 완료된 Notion/Linear 스타일 플랫 리디자인(`docs/tasks/notion-style-ui-refresh/`)의 후속 다듬기 작업이다.
- 사용자가 가이드 문서 화면의 완성도를 계속 높이고자 요청함 — 레이아웃 구조 정리(TOC 분리/중앙 정렬)와 플로팅 검색 UI 마감(보더/높이/라운드)을 이번 스코프로 확정.
- `@sfood/ui` 디자인 시스템 CSS 토큰(색상/라운드/폰트 등)만 사용하고 하드코딩된 값 도입을 금지한다.

## Scope
- `ArticlePage.tsx`, `StartingGuidePage`(`GuidesPage.tsx`)가 공유하는 `.article-layout` 그리드 구조를 조정하여 TOC(`.article-aside`)를 컨텐츠와 명확히 분리된 우측 사이드 패널로 유지하면서, 컨텐츠 컬럼 자체는 사용 가능한 폭 안에서 중앙 정렬되도록 한다.
- `.article-ask-dock`(플로팅 검색 패널)의 가로 위치/폭을 컨텐츠 컬럼의 중심·폭과 시각적으로 일치시킨다.
- `.article-ask` / `.article-ask-form`의 이중 보더 구조를 제거(바깥 프레임 하나만 유지)하고, 패널 높이(`COLLAPSED_HEIGHT`/`EXPANDED_HEIGHT` 등 관련 상수 및 CSS)를 더 낮춰 콤팩트하게 만들고, 기존 `--radius-lg`보다 더 부드러운 라운드 토큰(`--radius-xl` 등 기존 디자인 시스템 토큰)을 적용한다.
- 라이트/다크 테마, 데스크톱(≥1280px)·모바일(≤390px) 뷰포트에서 모두 자연스럽게 보이도록 검증한다.

## Out Of Scope
- 텍스트 드래그 선택 → 컨텍스트 메뉴 → "질문하기" 버튼 → Ask 인풋 포커스 이동 기능 — 별도 태스크로 진행 예정(이번 스펙에 포함하지 않음).
- TOC 스크롤 동기화, 뒤로가기 버튼 위치, eyebrow 라벨, 제목 `[Type]` 접두어 제거 로직 — 직전 태스크에서 이미 구현·검증 완료, 이번 스코프에서 재작업하지 않음.
- Surface별 docType(guide/page) 노출 규칙 — CLAUDE.md에 동결된 규칙이며 변경하지 않음.
- `@sfood/ui`의 React 컴포넌트(JS) 교체 — 이 샌드박스 환경에서 dist 빌드가 최종 반영되지 않는 알려진 제약으로, 이번에도 CSS 토큰 레벨 작업만 수행한다.
- `/guides` 목록 페이지, 홈 화면, 검색 페이지의 레이아웃 — 이번 스코프는 문서 상세(가이드) 페이지에 한정한다.

## User Or Operator Scenarios
- 사용자가 가이드 상세 페이지를 넓은 데스크톱 화면에서 열면, 목차는 우측에 독립된 패널로 고정되어 있고, 본문은 목차와 무관하게 화면(또는 컨텐츠 영역) 중앙에 정렬되어 읽기 편하다.
- 사용자가 페이지 하단의 플로팅 검색창을 보면, 그 폭과 좌우 위치가 본문 컬럼과 시각적으로 정렬되어 있어 별도로 붕 떠 보이지 않는다.
- 사용자가 검색창을 보면 이중 테두리 없이 하나의 부드러운 라운드 프레임으로 보이고, 이전보다 낮은 높이로 컨텐츠 공간을 덜 차지한다.
- 모바일 뷰포트에서는 TOC가 기존과 동일하게(그리드가 1컬럼으로 접히는 기존 동작) 자연스럽게 처리된다 — 이번 스펙에서 모바일 동작을 새로 정의하지 않고 회귀만 확인한다.

## Acceptance Criteria
- AC1: `ArticlePage`, `StartingGuidePage`(agent-start/start 라우트) 양쪽에서 TOC가 우측 사이드 패널로 컨텐츠와 시각적으로 분리되어 보인다(데스크톱 ≥1280px).
- AC2: 컨텐츠 컬럼이 (TOC 유무와 무관하게) 사용 가능한 폭 안에서 중앙 정렬되어 보인다.
- AC3: `.article-ask-dock`의 좌우 위치·폭이 컨텐츠 컬럼과 시각적으로 정렬된다.
- AC4: Ask 패널에 보더가 하나만 보이고(이중 보더 제거), 기존보다 낮은 높이, 더 부드러운 라운드로 렌더링된다.
- AC5: 라이트/다크 테마 모두에서 위 변경이 깨지지 않는다.
- AC6: 모바일 뷰포트(390px)에서 가로 스크롤(overflow)이나 레이아웃 깨짐이 발생하지 않는다.
- AC7: `pnpm --filter @sfood/web typecheck`, `pnpm --filter @sfood/web test`, `pnpm --filter @sfood/web build`가 모두 통과한다.
- AC8: Playwright MCP로 데스크톱/모바일, 라이트/다크 조합의 실제 렌더링을 확인한다.

## Edge Cases
- TOC가 없는 문서(헤딩 0개, `document.headings.length === 0`)에서도 컨텐츠 중앙 정렬이 깨지지 않아야 한다.
- Ask 패널이 확장(EXPANDED_HEIGHT)된 상태에서도 컨텐츠 컬럼 정렬 기준과 폭이 유지되어야 한다.
- `xl` 브레이크포인트 미만(TOC가 그리드에서 접히는 좁은 화면)에서 컨텐츠 중앙 정렬 로직이 TOC 분리 전제와 충돌하지 않아야 한다.

## Assumptions
- "우측 사이드 패널로 분리"는 완전히 별도의 컴포넌트 트리로 분리하라는 뜻이 아니라, 시각적으로(간격/배경/구분선 등 토큰 기반 스타일로) 컨텐츠와 명확히 구분되는 고정 사이드 영역으로 두는 것을 의미한다고 해석한다.
- "검색 기능 크기를 컨텐츠 길이와 동일하게 맞춘다"는 것은 Ask 패널의 가로 폭/중심축을 본문 컬럼과 일치시키는 것을 의미하며, 세로 높이는 별도 요구사항(더 작게)으로 처리한다.
- 라운드 처리는 기존 `@sfood/ui` 토큰(`--radius-lg`, `--radius-xl` 등) 범위 내에서 더 큰 값으로 조정하는 것을 의미하며, 새로운 임의의 px 값을 하드코딩하지 않는다.

## Clarifications
- Q: 1~3번 스타일 수정 범위도 spec.md를 먼저 작성할지, 바로 구현할지?
  A: spec.md 먼저 작성 (사용자 선택).
- Q: 텍스트 드래그 선택 → 질문하기 기능을 이번 스펙에 포함할지?
  A: 포함하지 않음. 별도 태스크로 추후 진행(사용자 선택).
