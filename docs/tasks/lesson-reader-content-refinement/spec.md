# lesson-reader-content-refinement Spec

## Problem Statement
서비스를 직접 확인한 사용자가 `/lesson` 목록과 레슨 리더 화면에 대해 10개 항목의 UI 피드백을 남겼다. 정리 후 사용자 확인을 받아 진행한다.

## Business Context
가독성(설명 노출/줄바꿈), 정보 밀도(목록 배치, 학습 흐름 간격), 불필요한 정보 제거(시간, 완료 표시)를 통해 실제 학습 화면의 사용성을 개선한다.

## Scope
1. `/lesson` 목록: 가로형(1열) 리스트로 재배치. 카드 설명을 `lesson.presentation` 첫 씬 텍스트 블록에서 뽑아 100자로 제한(제목 중복 버그 해결 겸함). "약 N분" 시간 표시 제거.
2. "완료" 관련 기능 전체 삭제: `completedLessonSlugs`/`markLessonCompleted`, 목록 카드 "완료" 배지, 리더 마지막 씬 "레슨 완료" 버튼 라벨 — 사용자 명시 지시("체크 및 표시는 다 삭제").
3. "대본" → "교육 설명"으로 개명, 기본 노출(토글 아님), 탭 제목 + 우측 "숨기기/보기" 버튼.
4. narration 텍스트를 문장 단위로 나눠 여러 문단으로 렌더링.
5. `transitionToNext` 안내를 본문 강조 배너에서 화면 우측 하단 고정 안내 카드로 변경.
6. 상단 진행률 카운터를 하단 풋터(이전/다음 버튼 사이)로 이동.
7. 씬 타이틀 폰트 축소, 타이틀-본문 및 전체 세로 간격 확대.
8. "학습 흐름" 드로어 리스트 간격 축소(스크롤 없이 더 많이 보이도록).

## Out Of Scope
- 레슨 진행 상태(`lastLessonSlug`/`lastSceneId`, "이어서 학습하기") 자체는 유지 — 이번에 삭제하는 것은 "완료" 체크/뱃지뿐.
- 코스 순서 계산 로직(`courseOutline`, `getGlobalScenePosition`) 변경 없음.

## User Or Operator Scenarios
- 사용자가 `/lesson`에서 23개 레슨을 한 줄씩(가로형) 훑어보며 100자 설명만 확인한다.
- 사용자가 레슨 화면에서 "교육 설명"을 기본으로 읽되, 필요하면 우측 "숨기기"로 접는다.
- 사용자가 마지막 씬에서도 "다음" 버튼만 보고, 완료 배지나 체크 표시를 보지 않는다.
- 사용자가 씬을 넘길 때 우측 하단에 다음 내용 안내가 살짝 뜬다(본문을 가리지 않음).

## Acceptance Criteria
- AC1: `/lesson` 카드가 가로 1열 리스트로, 설명은 100자 이하, 시간 표시 없음.
- AC2: `completedLessonSlugs`/`markLessonCompleted`/완료 배지/"레슨 완료" 라벨이 코드 전체에서 제거됨.
- AC3: "교육 설명" 섹션이 기본 노출되고 우측 "숨기기/보기"로 토글 가능.
- AC4: narration이 여러 문단으로 나뉘어 렌더링되고, 소수점·문장부호 뒤 공백 없는 케이스에서 글자가 유실되지 않음.
- AC5: `transitionToNext` 배너가 화면 우측 하단에 고정 표시됨.
- AC6: 진행률 카운터가 하단 풋터에 있음.
- AC7: 학습 흐름 드로어가 이전보다 조밀하게 표시됨.

## Edge Cases
- `lesson.presentation` 첫 씬에 텍스트 블록이 없는 경우(customHtml만 존재) → `lesson.summary`로 폴백.
- narration에 소수점 숫자가 포함된 경우 → 문장이 소수점에서 잘리지 않음.
- narration에 문장부호 뒤 공백이 없는 경우 → 그래도 문장 단위로 분리됨.

## Assumptions
- 실 콘텐츠는 레슨:씬이 항상 1:1이라 목록 카드 설명은 사실상 "레슨의 유일한 씬" 텍스트다.

## Clarifications
- Q: 마지막 씬 완료 표시를 상단 뱃지로 이동할지, 완전히 삭제할지?
- A: 완전히 삭제(사용자 지시: "레슨 완료, 체크 및 표시는 다 삭제하는 걸로 하자").
