# Search Answer Readability Tone Result

검색 결과 답변의 읽기 흐름을 보정했다.

- AI 답변 지침서에 문단당 1-2문장, 문단 사이 빈 줄, 긴 설명의 문단 분리 규칙을 추가했다.
- 기술 용어 부가 설명은 괄호가 아니라 다음 문장이나 짧은 별도 문단으로 쓰도록 지침을 강화했다.
- 검색 프롬프트의 system/user 요구사항에 같은 규칙을 반영했다.
- 검색 답변 UI에서 긴 단일 설명 문단은 2문장 단위로 나눠 렌더링되도록 보정했다.
- 검색 답변 본문에 `바로 할 일`, `예시`, `확인`, `확인 포인트`, `주의`, `확인 필요` 같은 고정 섹션 제목을 만들지 않도록 프롬프트를 강화했다.
- 검색 화면에서 `immediateActions`, `exampleCommands`, `verificationChecks`, `cautions`를 별도 스타일 섹션으로 보여주지 않고, 필요한 경우 같은 답변 스타일의 자연스러운 보충 문단/목록으로 보존하도록 했다.
- 프롬프트에서 답변이 3줄 수준의 티저로 얇아지지 않도록, 3-5개 짧은 문단 또는 짧은 문단과 압축된 목록 수준의 충분한 설명을 요구하도록 보정했다.
- 답변 본문 내 페이지 링크는 기본 상태에서도 핑크 배지 형태로 보여 클릭 가능한 문서 링크임을 알 수 있게 했다.
- 정책 반영 안내에는 서버가 선택한 정책 컨텍스트의 원천 문서 링크를 함께 표시하도록 했다.
- 정책 원천 링크가 있으면 모델이 정책 안내 문구를 비워도 기본 안내 문구와 함께 정책 반영 박스를 노출하도록 했다.
- `mcp 설정페이지가 있지 않아?`처럼 페이지/문서/가이드/링크 존재 여부를 묻는 검색 질문은 `page-lookup`으로 분류해, 주제 설명보다 검색 결과 확인 여부와 일치/근접 페이지 링크를 먼저 답하도록 했다.
- 검색 입력창, 사용자 질문, AI 답변 본문, 답변 내 heading 폰트 크기를 분리해 검색 입력은 15px, 사용자 질문은 14px, AI 답변 본문은 15px, 주요 heading은 17-19px 굵은 글씨로 보이게 했다.
- 목록, 코드 블록, 표 파싱은 변경하지 않았다.

검증은 wiki-core/web 테스트, 패키지 타입체크, 전체 테스트, 전체 타입체크로 완료했다.
