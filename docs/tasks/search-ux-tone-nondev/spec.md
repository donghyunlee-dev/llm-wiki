# Spec: 검색 UX·답변 톤 개선 (비개발자 사내 직원 대상)

## 문제

현재 검색 답변과 아티클 Ask 답변이 초·중급 바이브코딩 사용자를 대상으로 안내하고 있으나,
실제 사용자는 **개발자가 아닌 사내 직원**이라는 점이 프롬프트와 지침서에 충분히 반영되어 있지 않다.
또한 추천 페이지와 관련 페이지 구분이 AI 판단이 아닌 단순 인덱스 슬라이스에 의존하고 있으며,
빈 검색어로 검색했을 때 시각적 피드백 없이 묵시적으로 실패한다.

## 범위

| 항목 | 포함 |
|------|------|
| 프롬프트 지침서 사용자 프로필 추가 | O |
| AI 프롬프트 비개발자 설명 강화 | O |
| 서버에서 추천/관련 페이지 분리 반환 | O |
| 클라이언트 섹션 렌더링 업데이트 | O |
| 빈 검색어 UX (URL 직접 접근 + 폼 제출 시) | O |
| 임베딩/시맨틱 검색 도입 | X |
| 아티클 Ask 캐싱 | X |
| 프로덕션 서버리스 AI 핸들러 | X |

## 수용 기준

1. AI 답변이 기술 용어(MCP, CLI, npm 등)를 처음 언급할 때 짧은 설명을 덧붙인다.
2. 답변 문체가 개발 지식 없는 독자도 이해할 수 있는 수준이다.
3. `추천 페이지`는 AI가 명시한 직접 관련 페이지로만 구성된다.
4. `관련 페이지`는 키워드 랭킹 기반 페이지 중 추천 페이지에 없는 것으로 구성된다.
5. 빈 URL(`/search`, `/search?q=`)로 접근 시 검색어 입력 안내 메시지가 표시된다.
6. 검색어 없이 폼을 제출하면 시각적 힌트가 표시된다.
7. 기존 searchRecommendations 테스트와 aiAsk 테스트가 통과한다.

## 엣지 케이스

- AI가 추천 페이지를 0개 반환하면 랭킹 기반 페이지 전체를 추천으로 올린다.
- 추천과 관련이 모두 비어 있어도 레이아웃이 깨지지 않아야 한다.
- 빈 검색어 힌트는 이전 대화 턴이 있어도 표시되지 않아야 한다.

## 가정

- 서버 응답 스키마에 `relatedDocuments` 필드를 추가해도 기존 캐시와 타입 계약에서 backward-compatible 하다.
- `docs/prd/ai-ask-prompt-guide.md`와 `search-flow-contract.md`가 코드보다 선행하는 기준 문서다.
