# Task Workspace Guide

Use `docs/tasks/{work-scope}/` for each non-trivial work item.

## Required Files
- `spec.md`: problem, scope, acceptance criteria, edge cases
- `plan.md`: approach, impacted areas, validation plan, risks
- `tasks.md`: implementation, testing, documentation, progress
- `test-result.md`: executed checks, outcomes, failures, retests
- `result.md`: delivered scope, changed files, decisions, gaps, next steps

## Naming Rule
- Use a short descriptive folder name such as `wiki-mvp-bootstrap` or `read-only-wiki-core`.
- Keep the same folder when the same work scope continues across sessions.
- Do not create synthetic numeric IDs just for documentation.

Copy the files from `docs/tasks/_template/` when starting a new task.
