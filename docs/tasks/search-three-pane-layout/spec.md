# search-three-pane-layout Spec

## Problem Statement
- 현재 `/search` 화면은 질문마다 사용자 메시지 + AI 답변 + 추천/관련/FAQ 문서가 답변 하단에 순서대로 쌓이는 단일 컬럼 챗 구조다. 대화 기록은 페이지 새로고침 시 사라지는 인메모리 state뿐이며, 대화 목록, 대화 전환, 대화 삭제 기능이 없다. 화면 구조가 최신 AI Agent UI(좌: 대화 목록 / 중: 연속 답변 / 우: 컨텍스트)와 비교해 구식이라는 피드백을 받았다.

## Business Context
- 사용자가 과거 질문을 다시 찾아보거나 여러 주제를 병렬로 오가며 위키를 탐색하기 어렵다. 대화 목록이 없어 매번 새로 질문해야 하고, 답변에 딸린 추천/관련 문서가 턴마다 흩어져 있어 한 대화에서 나온 전체 참고 문서를 한눈에 보기 어렵다.

## Scope
- `/search` 화면을 좌(대화 목록)/중(연속 답변)/우(컨텍스트 패널) 3단 레이아웃으로 재구성. 사이트 헤더(`SiteHeader`)는 기존 그대로 유지하고, 그 아래 본문 영역만 3단으로 분할한다.
- 브라우저 localStorage 기반 대화 목록 신규 구현: 생성, 목록 조회, 선택/전환, 삭제(확인 다이얼로그 포함), 최신 대화 순 정렬, 최대 20개 보관(초과 시 가장 오래된 것부터 자동 삭제).
- 대화 제목은 AI 검색 응답에 `title` 필드를 추가해 자동 생성(첫 턴에서만 설정, 이후 턴에서 갱신하지 않음). 필드가 비어 있으면 첫 질문 앞부분으로 대체.
- 우측 컨텍스트 패널: 추천 페이지 → 관련 페이지 → FAQ 순서로 세로 스택, 섹션 헤더로 구분. 현재 열려 있는 대화의 **모든 턴**에서 나온 문서를 섹션별로 누적하고, 문서 id 중복 시 가장 최근 턴 기준으로 재배치(섹션도 최신 턴 기준으로 재산정).
- 모바일/좁은 화면: 중앙 답변 스트림만 기본 노출, 좌/우 패널은 드로어(토글)로 전환.
- 새 대화 시작은 홈/검색창에서 질문할 때만 발생(항상 새 `StoredConversation` 생성). `/search` 화면 하단 입력창에서 이어서 질문하면 현재 열려 있는 대화에 턴이 추가된다(기존 멀티턴 동작 유지).

## Out Of Scope
- Surface별 docType 노출 규칙 변경 (`buildFeaturedGuides`, `CategoryPage` guides 필터 등) — CLAUDE.md에 동결된 규칙이며 이 작업에서 건드리지 않는다.
- 검색 API의 추천/관련 문서 산정 로직(`recommendedDocuments`/`relatedDocuments` 서버 계산 방식) 변경 — 클라이언트에서 누적/중복 제거 방식만 다르게 처리하고, 서버 산정 규칙 자체는 그대로 재사용한다.
- 대화 목록을 서버/DB에 저장하는 기능(다중 기기 동기화 등) — 이번 작업은 브라우저 로컬 저장만 다룬다.
- 대화 목록 검색/필터링 기능 — 이번 스코프에서는 최신순 목록 표시와 삭제만 지원한다.

## User Or Operator Scenarios
- 사용자가 홈에서 질문을 입력하면 `/search`로 이동하고, 좌측 목록에 새 대화가 최상단에 생성되며 답변이 도착하면 자동으로 제목이 붙는다.
- 사용자가 `/search` 화면 하단 입력창으로 후속 질문을 이어가면 같은 대화에 턴이 추가되고, 우측 패널의 추천/관련/FAQ 문서가 누적 갱신된다.
- 사용자가 좌측 목록에서 과거 대화를 클릭하면 해당 대화의 전체 턴과 우측 컨텍스트 패널이 그대로 복원된다.
- 사용자가 대화 목록 항목의 삭제 아이콘을 클릭하면 확인 다이얼로그가 뜨고, 확인 시 대화가 삭제된다. 현재 보고 있던 대화를 삭제하면 다음 대화(없으면 빈 상태)로 전환된다.
- 사용자가 모바일에서 `/search`에 진입하면 중앙 답변만 보이고, 버튼으로 좌측 대화 목록 또는 우측 컨텍스트 패널을 드로어로 열어볼 수 있다.

## Acceptance Criteria
- AC1: `/search`가 데스크톱에서 좌/중/우 3단 레이아웃으로 렌더링되고, 사이트 헤더는 다른 페이지와 동일하게 유지된다.
- AC2: 질문 제출 시 localStorage에 대화가 생성/갱신되고, 새로고침 후에도 좌측 목록과 대화 내용이 복원된다.
- AC3: 대화 목록은 `updatedAt` 내림차순으로 정렬되고, 21번째 대화가 생기면 가장 오래된 대화가 자동 삭제된다.
- AC4: 대화 삭제는 확인 다이얼로그를 거쳐야 실행되며, 삭제 후 목록과 화면이 올바르게 갱신된다.
- AC5: 우측 패널은 추천/관련/FAQ 섹션이 구분되어 보이고, 같은 대화의 여러 턴에서 나온 문서가 중복 없이, 최신 턴 기준으로 재배치되어 누적 표시된다.
- AC6: 모바일 뷰포트에서 좌/우 패널이 드로어로 토글되고, 중앙 답변 스트림은 항상 접근 가능하다.
- AC7: AI 검색 응답에 `title` 필드가 추가되고, 첫 턴 완료 시 대화 제목으로 반영된다. 필드가 비어 있으면 첫 질문 텍스트로 대체된다.

## Edge Cases
- 답변 대기 중(로딩 상태)에 새로고침하면 해당 진행 중 턴은 저장되지 않아 유실된다 — 허용된 트레이드오프로 문서화하고 별도 복구 로직은 만들지 않는다.
- 첫 턴에서 AI가 `title`을 반환하지 않으면 첫 질문 텍스트(길면 잘라서) 를 제목으로 사용한다.
- 동일 문서가 한 대화 내에서 어떤 턴엔 "추천", 다른 턴엔 "관련"으로 분류된 경우, 최신 턴의 분류를 최종값으로 사용한다.
- localStorage 접근이 차단된 환경(프라이빗 모드 등)에서는 대화 저장에 실패할 수 있다 — 실패해도 현재 세션의 대화/답변 조회 자체는 계속 동작해야 한다(저장 실패가 검색 기능을 막지 않음).
- 완전 미지원 응답(`confluenceData` 비어 있음)인 턴은 기존 규칙대로 추천/관련/FAQ를 비운 채로 누적 로직에 반영한다(빈 값이 다른 턴의 문서를 지우지 않음).

## Assumptions
- 기존 `/api/wiki/ai/search` 응답 스키마 변경(`title` 필드 추가)은 하위 호환을 유지하며, 기존 클라이언트 로직에는 영향 없다.
- localStorage 용량 제한(브라우저별 통상 5~10MB) 안에서 대화 20개 보관은 안전한 범위로 간주한다.
- 우측 패널의 턴별 출처 표시(어느 질문에서 나온 카드인지)는 이번 스코프에 포함하지 않는다.

## Clarifications
- Q: 오른쪽 사이드바는 현재 턴만 보여줄까, 전체 턴 누적으로 보여줄까? A: 전체 턴 누적.
- Q: 대화 목록 제목은 어떻게 정할까? A: AI 요약 제목(기존 검색 응답에 `title` 필드 추가하는 방식).
- Q: 새 대화는 어떻게 시작할까? A: 홈/검색창에서 질문하면 항상 새 대화, `/search` 내 이어서 질문은 기존 대화에 턴 추가.
- Q: 대화 삭제 시 확인 절차가 필요할까? A: 확인 다이얼로그 표시.
- Q: localStorage 보관 개수 제한이 필요할까? A: 20개, 초과 시 오래된 것부터 자동 삭제.
- Q: 오른쪽 패널 섹션 구분 방식은? A: 세로 스택 + 섹션 헤더(탭 방식 대신).
- Q: 전체 레이아웃 구조(헤더 처리 포함)는? A: 기존 `SiteHeader` 그대로 유지, 그 아래 본문만 3단.
- Q: 모바일/좁은 화면 처리는? A: 중앙 답변만 기본 노출, 좌우는 드로어/토글로 숨김.
