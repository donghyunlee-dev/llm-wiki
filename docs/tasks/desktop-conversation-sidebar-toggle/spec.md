# desktop-conversation-sidebar-toggle Spec

## Problem Statement
데스크톱(`lg` 이상)에서 좌측 "최근 대화" 사이드바는 항상 고정폭으로 표시되며 닫을 방법이 없다. 모바일에는 드로어 열기/닫기가 있지만, 데스크톱에서는 그 화면 공간을 접어 넓게 쓰고 싶을 때 방법이 없다.

## Business Context
사용자가 "왼쪽 대화 목록 닫고 열기 버튼 구현"을 요청. 조사 결과 `isConversationDrawerOpen` state와 `.search-sidebar-open` 클래스는 모바일 드로어 전용(`max-lg` 브레이크포인트에서만 트랜지션 적용)이라, 데스크톱에는 접기 기능이 전혀 없었다.

## Scope
- 홈(`HomePage.tsx`)과 검색(`SearchPage.tsx`) 양쪽에 데스크톱(`lg` 이상)용 좌측 대화 목록 사이드바 접기/펼치기 토글 버튼 추가.
- 사이드바가 접혀 있을 때도 다시 펼 수 있는 버튼을 항상 노출.

## Out Of Scope
- 모바일 드로어(`isConversationDrawerOpen`) 동작 변경.
- 우측 컨텍스트 패널(`search-sidebar-right`)의 접기 기능(요청 범위 아님).
- 접힘 상태를 localStorage 등에 영속화(요청에 없었으므로 세션 내 상태로만 유지).

## User Or Operator Scenarios
- 데스크톱에서 사용자가 토글 버튼을 누르면 좌측 대화 목록 사이드바가 사라지고 메인 콘텐츠 영역이 넓어진다.
- 접힌 상태에서 같은 토글 버튼을 다시 누르면 사이드바가 다시 나타난다.
- 모바일(`lg` 미만)에서는 기존 드로어 동작이 그대로 유지된다.

## Acceptance Criteria
- AC1: 데스크톱 뷰포트에서 토글 버튼 클릭 시 좌측 사이드바가 사라진다.
- AC2: 사이드바가 사라진 상태에서도 같은 버튼(또는 동일 위치의 버튼)으로 다시 열 수 있다.
- AC3: 모바일 뷰포트에서는 기존 드로어 열기/닫기 동작에 회귀가 없다.
- AC4: 홈과 검색 페이지 양쪽에 동일하게 적용된다.

## Edge Cases
- 홈 화면은 `hasConversations`가 false면 사이드바 자체를 렌더링하지 않는 기존 동작 유지 — 대화가 없으면 토글 버튼도 노출하지 않는다.
- 검색 페이지는 대화 유무와 무관하게 항상 사이드바를 렌더링하는 기존 동작을 유지 — 토글 버튼도 항상 노출한다.

## Assumptions
- 접기 방식은 애니메이션 트랜지션 없이 단순히 보이기/숨기기(`hidden`)로 구현해도 요구사항을 충족한다(과도한 구현 지양, 사용자가 트랜지션을 명시적으로 요청하지 않음).
- 접힘 상태는 페이지 새로고침 시 초기화되어도 무방하다(영속화 요청 없음).

## Clarifications
- Q: 데스크톱 토글을 지금 진행할지?
- A: 예, 진행(사용자 승인).
