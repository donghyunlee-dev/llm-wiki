# Spec: Playbook 검색 로깅

## 문제

사용자가 wiki에서 검색한 내용이 wiki에 없을 수 있음.
현재는 어떤 질문이 들어왔고 wiki가 얼마나 충분하게 답변했는지 추적하는 방법이 없음.
검색 기록을 Confluence에 저장하여 자동 업데이트 에이전트의 입력 데이터로 활용하는 것이 목적.

## 범위

### 포함

- 사용자가 `/api/wiki/ai/search`를 통해 검색할 때 결과를 Confluence Playbook 페이지에 자동 기록
- 일별 페이지 단위로 기록 (예: `Playbook - 2026-05-19`)
- 페이지가 없으면 생성, 있으면 기존 페이지에 항목 추가
- 각 일별 페이지는 하나의 로그 테이블을 유지하고, 검색 1건을 한 행으로 누적
- 각 항목에 포함할 내용:
  - 검색 일시
  - 검색 질문 원문
  - AI 응답 요약 (첫 200자)
  - 검색 결과 (추천 문서 제목 목록)
  - 충분도 판단: `충분` / `부족`
  - 부족한 경우: 부족했던 키워드 목록
- 로깅은 검색 응답을 사용자에게 먼저 반환한 후 비동기로 처리 (응답 지연 없음)

### 제외

- 아티클 페이지 `문서 질문` (AI Ask) 기록은 미포함 — 검색 로그만 대상
- Playbook 페이지 읽기/렌더링 변경 없음
- 프론트엔드 UI 변경 없음
- 로그 삭제/수정 API 없음

## 시나리오

### 정상 흐름
1. 사용자가 검색 → `/api/wiki/ai/search` 응답 생성
2. 응답 반환 (사용자 대기 시간에 영향 없음)
3. 비동기로 Confluence Playbook 일별 페이지의 로그 테이블에 행 추가

### 일별 페이지 없음
- Confluence에서 해당 일자 페이지 조회 → 없으면 `Playbook` 부모 페이지 아래 신규 생성
- 이후 항목 추가

### Confluence 쓰기 실패
- 로깅 실패 시 서버 콘솔에만 오류 기록
- 검색 응답에는 영향 없음 (silent fail)

### 충분도 판단 기준
- `충분`: AI 응답이 wiki 문서에서 직접 근거를 찾은 경우 (`supportedByContext: true` 또는 추천 문서 2개 이상)
- `부족`: `supportedByContext: false` 또는 `unsupportedClaims` 존재 또는 추천 문서 1개 이하

## 수용 기준

1. 검색 완료 후 Confluence Playbook 일별 페이지에 항목이 추가된다
2. 항목에는 검색 일시, 질문, 응답 요약, 추천 문서, 충분도, 부족 키워드가 포함된다
3. 사용자 응답 시간에 영향이 없다 (비동기)
4. Confluence 쓰기 실패 시 검색 응답에 영향이 없다
5. 일별 페이지가 없으면 자동 생성된다
6. 같은 일자에 여러 검색이 발생해도 페이지 본문에는 로그 테이블이 하나만 있고 행만 추가된다

## 엣지 케이스

- Confluence 쓰기 권한이 없는 경우: 오류 무시, 로그만 출력
- 검색 결과가 없는 경우 (`topDocuments.length === 0`): 로깅하되 추천 문서는 빈 목록
- Playbook 부모 페이지 ID를 환경변수로 분리하여 공간 이동 시 대응 가능하게 함

## 가정

- Confluence API 토큰은 쓰기 권한을 포함하고 있음
- Playbook 부모 페이지 ID: 별도 확인 필요 (현재 `ALLOWED_REMOTE_TITLES`에 "Playbook"으로 등록)
- 일별 페이지 타이틀 형식: `Playbook - YYYY-MM-DD`
- Confluence 페이지 본문은 storage format (XHTML) 사용
