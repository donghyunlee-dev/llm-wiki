# guide-page-text-selection-ask Spec

## Problem Statement
가이드 문서(`ArticlePage`) 본문에서 사용자가 궁금한 부분을 드래그로 선택했을 때, 그 텍스트를 손으로 복사해 하단 Ask 패널에 붙여넣는 수고 없이 바로 질문으로 이어갈 방법이 없었다.

## Business Context
`docs/tasks/guide-page-toc-sidebar-refresh/`에서 사용자가 함께 요청했으나, 새 인터랙션 기능이라 별도 스코프로 분리하기로 합의했다(해당 태스크의 `result.md` "Open Gaps"/"Next Steps" 참고). Medium/Notion/Google Docs류에서 널리 쓰이는 "텍스트 선택 → 플로팅 버튼 → 액션" 패턴을 그대로 적용한다.

## Scope
- 적용 대상: `ArticlePage`에서 렌더링되는 문서 본문(`.article-body` 내부)만.
- 코드블록/표를 포함한 본문 내 모든 선택 가능 텍스트에서 동일하게 동작(콘텐츠 종류별 예외 처리 없음).
- 여러 문단/헤딩에 걸친 선택도 표준 `Selection`/`Range` API로 그대로 처리.
- 데스크톱(마우스 드래그)과 모바일(터치 롱프레스 네이티브 선택) 모두 동일한 컴포넌트로 지원.
- 선택 텍스트가 500자를 초과하면 "..."으로 잘라 Ask 인풋에 채운다.

## Out Of Scope
- `StartingGuidePage`(`/guides/agent-start`, `/guides/start`) — Ask 패널 자체가 없어 이번 스코프에서 제외.
- 검색 페이지, 홈 등 다른 화면으로의 기능 확장.
- 선택 텍스트 자동 전송(사용자가 직접 확인 후 전송해야 함).
- 하이라이트 영구 저장, 코멘트 스레드 등 주석 기능.

## User Or Operator Scenarios
- 사용자가 가이드 본문에서 문장을 드래그하면 선택 영역 위(공간 부족 시 아래)에 "질문하기" 버튼이 뜬다.
- 버튼 클릭 시 하단 Ask 패널의 질문 인풋에 선택 텍스트가 채워지고 포커스가 이동한다.
- 선택 해제, 스크롤(내부 스크롤 컨테이너 포함), 바깥 클릭, `Esc` 시 버튼이 사라진다.
- 코드블록/표 안의 텍스트를 선택해도 동일하게 동작한다.
- 매우 긴 범위를 선택해도 500자로 잘려 인풋에 채워진다.
- 선택 영역이 본문 컨테이너 바깥까지 걸치면(예: TOC까지 드래그) 버튼이 뜨지 않는다.

## Acceptance Criteria
- AC1: 본문 내 텍스트 선택 시 "질문하기" 플로팅 버튼이 선택 영역 기준 위/아래에 표시된다.
- AC2: 버튼 클릭 시 Ask 패널 인풋에 선택 텍스트가 채워지고 포커스가 이동한다(실제 브라우저 마우스 클릭으로 확인, 합성 이벤트가 아님).
- AC3: 선택이 컨테이너 바깥으로 걸치면 버튼이 뜨지 않는다.
- AC4: 스크롤(페이지 전체 및 코드블록/표 등 내부 스크롤 컨테이너 포함), 바깥 클릭, `Esc`, 선택 해제 시 버튼이 사라진다.
- AC5: 500자 초과 선택은 "..."으로 잘려 전달된다.
- AC6: 라이트/다크, 데스크톱(1280px)/모바일(390px)에서 정상 동작하고 레이아웃 회귀가 없다.
- AC7: `pnpm --filter @sfood/web typecheck`/`test`/`build` 통과.
- AC8: Playwright MCP로 실제 브라우저 검증, Codex 크리티컬 리뷰 수행 및 발견 사항 반영.

## Edge Cases
- 선택이 컨테이너 경계를 걸쳐 있는 경우(`anchorNode`/`focusNode` 중 하나라도 컨테이너 바깥) — 버튼 미노출.
- 버튼 클릭 시 브라우저가 mousedown에서 선택을 collapse시켜 클릭이 유실될 수 있는 문제 — `onMouseDown`에서 `preventDefault()`로 방지(Codex 리뷰에서 발견).
- 코드블록/표 등 내부 스크롤 컨테이너에서 스크롤 시 버튼이 stale한 좌표에 남는 문제 — `document`의 캡처 단계 `scroll` 리스너로 해결(Codex 리뷰에서 발견).
- 선택 영역이 뷰포트 상단 가까이 있어 버튼을 위에 놓을 공간이 없는 경우 — 아래로 배치 전환.

## Assumptions
- 키보드만으로 텍스트를 드래그 선택해 이 기능을 트리거하는 경로는 없다 — 기존에도 없던 경로이므로 회귀가 아니며, 하단 Ask 패널이라는 대체 경로가 항상 존재한다.
- 500자 트렁케이트 길이는 인풋 사용성을 위한 잠정 값이며, 필요 시 이후 조정 가능하다.

## Clarifications
- Q: 1~3번(TOC/레이아웃) 스타일 수정과 함께 진행할지, 별도로 진행할지?
  A: 별도 진행(사용자 선택) — 이 태스크가 그 결과물이다.
- Q: 어떤 UI 패턴을 기준으로 설계할지 시각적 목업을 볼지?
  A: 브라우저 목업 없이 업계 표준 패턴(Medium/Notion/Google Docs) 기준으로 바로 설계 진행(사용자 선택).
